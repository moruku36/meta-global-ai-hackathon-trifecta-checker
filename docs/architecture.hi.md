## 1. उद्देश्य

एआई एजेंटों के लिए एक उड़ान-पूर्व सुरक्षा जांच, जो गैर-विशेषज्ञों के लिए है। उपयोगकर्ता
अपने शब्दों में बताता है कि उसका एजेंट क्या कर सकता है; चेकर यह मूल्यांकन करता है
कि क्या शक्तियों का वह संयोजन "लीथल ट्राइफेक्टा" है (साइमन
विलिसन) — निजी-डेटा पहुंच × अविश्वसनीय-सामग्री के संपर्क × बाहरी
संचार — और परिणाम को सरल भाषा में समझाता है, एक ठोस
सुधार के साथ (एजेंट को विभाजित करें, भेजने पर रोक लगाएं)।

स्थिति: डिज़ाइन-समय निदान। यह रनटाइम प्रवर्तन
उपकरणों (जैसे NVIDIA OpenShell) का पूरक है और लेखक का पूर्व कार्य
`ai-governance-control` (*विकास* परिवेश के लिए अभिशासन)।
Meta का "Agents Rule of Two" रेटिंग तर्क का सबसे निकट प्रकाशित संबंधी है।

## 2. वास्तुकला

```
Browser (single static page, chat UI)
   │  HTTPS / JSON
   ▼
Vercel serverless functions (Python, stdlib only)
   ├── POST /api/check          text ─▶ profile + verdict (+ unclear list)
   ├── POST /api/check-profile  profile ─▶ verdict        (0 LLM calls)
   ├── POST /api/explain        verdict ─▶ plain-language explanation
   └── POST /api/followup       message ─▶ conversational reply (+ action)
   │
   ▼
Meta Model API — Muse Spark 1.3 (api.meta.ai, OpenAI-compatible)
   used ONLY for: extraction, explanation, follow-up conversation
```

कोई डेटाबेस नहीं, कोई बिल्ड चरण नहीं, कोई सर्वर-साइड सत्र नहीं: क्लाइंट वर्तमान
प्रोफ़ाइल/निर्णय को पृष्ठ स्थिति में रखता है और प्रत्येक कॉल के साथ उसे फिर से भेजता है।

## 3. घटक

- **`trifecta_checker.py` — नियतात्मक नियम इंजन।** निर्णय कभी
  एलएलएम से नहीं आता। बंद क्षमता शब्दावली:
  - DATA_ACCESS {gmail_read, email_read, calendar_read, local_files,
    drive_read, contacts_read, message_read}
  - UNTRUSTED {web_browse, email_body, uploaded_files, webhook, chat_input}
  - OUTBOUND {email_send, chat_post, http_post, message_send,
    code_execute_outbound}
  - AMPLIFIERS {no_human_approval, auto_execute_code,
    long_term_memory_write}
  - नियम: 3 तत्व = **Lethal**; 2 तत्व, या 1 + प्रवर्धक =
    **Risky**; अन्यथा **Low**। हर निर्णय में साक्ष्य होता है (किस
    टोकन से कौन सा तत्व बना) और एक पृथक्करण प्रस्ताव (केवल-पढ़ने वाला
    Reader + अनुमति-सूची वाला अनुमोदन-नियंत्रित Sender)।
- **`extract.py` — सुरक्षा उपायों सहित Spark निष्कर्षण।** मुक्त पाठ → प्रोफ़ाइल
  JSON जो बंद शब्दावली तक सीमित है। अमान्य टोकन केवल एक
  मरम्मत कॉल को ट्रिगर करते हैं जो मॉडल को अनुमत शब्दावली दिखाता है; यदि आउटपुट
  फिर भी फिट नहीं होता, तो निष्कर्षण जोर से विफल होता है (कोई अनुमान नहीं)। परिणाम
  `unclear` पहलुओं को भी सूचीबद्ध करता है — {reads_private,
  reads_untrusted, sends_out, human_approval} का एक परिष्कृत उपसमूह — जो यह बताता है कि
  विवरण में क्या खुला रह गया है।
- **`explain.py` — निर्णय → मैत्रीपूर्ण व्याख्या।** पांच भाषाओं (en/ja/zh/hi/es) में निश्चित शीर्षक: Verdict / What could happen / How to
  fix it / Bottom line / Next steps।温め नहीं, गर्म, रोज़मर्रा के शब्दों वाला लहजा; "Next
  steps" कोमल सुझाव हैं जो एक आमंत्रित करने वाले प्रश्न के साथ समाप्त होते हैं।
- **`check.py` — पाइपलाइन + अनुवर्ती वार्तालाप।** प्रवाह को विभाजित करता है
  `extract_and_judge` (1 LLM कॉल), `judge_profile` (0 कॉल),
  `explain_result` (1 कॉल, विफलता घातक नहीं) और `followup` (Spark
  UI भाषा में उत्तर देता है, केवल सरल शब्दों में, कभी कच्चे टोकन नहीं; 
  मॉडल विभाजन दृश्य को ट्रिगर करने के लिए `[[SPLIT]]` के साथ समाप्त कर सकता है, या जब
  उपयोगकर्ता किसी भिन्न एजेंट का वर्णन करता है तो `[[NEW]]` उत्तर दे सकता है) में।
- **`llm.py` — साझा Spark कॉलर।** होस्टेड: `META_API_KEY` पर्यावरण चर →
  api.meta.ai पर सीधी कॉल। स्थानीय विकास: वॉल्ट में रखी कुंजी पर
  एक सहायक सबप्रोसेस के माध्यम से फॉलबैक (कुंजी कभी कोड या लॉग में नहीं दिखती)।
- **`app.py` — वेब क्लाइंट जनरेटर।** एक स्थिर HTML पृष्ठ: केवल-चैट
  UI जिसमें एक शुभंकर (Trafica) है, पूरे UI को चलाने वाला भाषा चयनकर्ता,
  ध्वनि इनपुट (Web Speech API), फ़ाइल संलग्नक, और नीचे वर्णित
  प्रति-प्रश्न तर्क। MCP कॉन्फ़िगरेशन JSON संलग्न करना (जैसे Claude
  Desktop / MCP क्लाइंट कॉन्फ़िग) क्लाइंट-साइड में उसके सर्वरों के सरल
  विवरण में सारांशित किया जाता है, जो फिर सामान्य
  निष्कर्षण से गुजरता है — ताकि किसी वास्तविक एजेंट कॉन्फ़िग को जस का तस
  जांचा जा सके (`fixtures/sample_mcp_config.json`)। पृष्ठ पाद में
  अनुमानी अस्वीकरण और डेमो के भागीदार क्रेडिट पर चलने के बारे में
  गोपनीयता नोट रहता है।

## 4. वार्तालाप डिज़ाइन

1. **अभिवादन।** Trafica अपना परिचय देता है: वह क्या जांचता है, और कैसे
   शुरू करें (एक उदाहरण वाक्य सहित)। वार्तालाप शुरू होने तक चुनी गई भाषा
   में फिर से रेंडर होता है।
2. **पहले शब्दों में निर्णय।** निर्णय बुलबुला एक बोले गए
   वाक्य से शुरू होता है ("मैंने देख लिया — निर्णय Risky है"), फिर बैज,
   मैत्रीपूर्ण तत्व चिप्स, और "3 में से n शक्तियों" की गिनती।
3. **प्रति-प्रश्न, अधिकतम एक प्रश्न।** क्लाइंट इंजन नियम को स्थानीय रूप से
   दोहराता है और केवल तभी पूछता है जब कोई `unclear` पहलू वास्तव में निर्णय बदल सकता है।
   उत्तर हां / नहीं / पता नहीं चिप्स हैं (टाइप करना भी चलता है)।
   उत्तर देने पर एक प्रतिनिधि संपादन लागू होता है और /api/check-profile के माध्यम से
   फिर से मूल्यांकन होता है। इसके बजाय टाइप करना प्रश्न को बाधित करता है और
   संयुक्त पाठ से फिर से निष्कर्षण करता है।
4. **निर्णय के बाद वार्तालाप।** अनुवर्ती प्रश्न Spark को /api/followup के माध्यम से
   जाते हैं; "क्या होगा अगर मैं इसे विभाजित कर दूं?" Reader/Sender हिस्सों को
   ताज़ा निर्णयों के साथ दिखाता है — Lethal → Risky + Low का डेमो चाप।

## 5. प्रमुख निर्णय और समझौते

- **चतुराई पर नियतात्मकता।** रेटिंग पुनरुत्पादनीय है: समान
  प्रोफ़ाइल, समान निर्णय। एलएलएम को अनुवादक माना जाता है, कभी निर्णायक नहीं।
  यही उत्पाद का मुख्य विश्वास दावा है।
- निष्कर्षण में मौन अनुमान पर जोरदार विफलता (एक बार मरम्मत, फिर
  visibly विफल)।
- **स्थितिहीन होस्टिंग।** Vercel मुफ्त स्तर, केवल-stdlib Python; कोई उपयोगकर्ता
  डेटा कहीं संग्रहीत नहीं होता। विवरण केवल Meta Model API को जाते हैं।
- **सार्वजनिक-डेमो API सुरक्षा।** सभी चार एंडपॉइंट `api_guard.py` साझा करते हैं:
  अनुरोध-निकाय आकार (64 KB) और प्रति-फ़ील्ड पाठ लंबाई पर कठोर सीमाएं,
  किसी भी LLM कॉल से पहले लागू, साथ ही सर्वोत्तम-प्रयास प्रति-IP दर सीमा
  (इन-प्रोसेस काउंटर — स्थितिहीन इंस्टेंस का अर्थ है कि यह भोले लूप को
  कुंद करता है बजाय वैश्विक सीमा की गारंटी के; कठोर सीमा के लिए
  साझा भंडार जैसे Vercel KV की आवश्यकता होगी)। सार्वजनिक UAT के लिए डेमो
  खोलने से पहले 2026-10-28 को जोड़ा गया।
- **मुफ्त-क्रेडिट चेतावनी।** जब तक भागीदार मुफ्त क्रेडिट उपयोग में हैं, प्रस्तुत
  सामग्री उत्पाद सुधार के लिए उपयोग की जा सकती है — UI के दर्शकों से
  नमूना विवरणों के साथ परीक्षण की अपेक्षा है, और यह UAT के लिए नोट किया गया है।
- **दायरे की ईमानदारी।** रेटिंग एक अनुमान है, मानक नहीं;
  ट्राइफेक्टा मुख्य रूप से डेटा चोरी को कवर करता है, हर एजेंट जोखिम को नहीं (व्यापक मानचित्र के लिए
  OWASP Agentic Top 10 संदर्भित है)।

## 6. सत्यापन

- **इंजन पुनरुत्पादनीयता (कोई LLM नहीं):** `tests/test_engine.py` छह
  मानक प्रोफ़ाइलों के साथ दो सीमा मामलों (एक तत्व + प्रवर्धक;
  कोई शक्ति नहीं) का मूल्यांकन करता है, प्रत्येक दो बार — 8/8 उत्तीर्ण, रनों में बाइट-समान निर्णय।
- **निष्कर्षण:** पाठ फिक्स्चर पर 4/4 सत्यापित (Low / Risky /
  Lethal / Lethal) इंजन के अपेक्षित निर्णयों के विरुद्ध। मरम्मत-पथ
  जांच (एक विवरण जिसने पहले एक गढ़ा हुआ टोकन उत्पन्न किया) ने पुष्टि की
  कि मरम्मत कॉल इसे बंद शब्दावली में सामान्य कर देती है और फिर भी
  सही निर्णय पर पहुंचती है; एक प्रोफ़ाइल जिसकी मरम्मत नहीं हो सकती, डिज़ाइन से
  जोर से विफल होती है।
- **ओपन-वेट पथ:** निष्कर्षण और व्याख्या को Muse Spark Open (`meta-models/muse-spark-open-1026` के माध्यम से
  Baseten) पर 2026-10-27 को शुरू से अंत तक चलाया गया — केस C निष्कर्षण ने सही
  प्रोफ़ाइल लौटाई, और जापानी और अंग्रेजी में व्याख्याएं सही ढंग से उत्पन्न हुईं।
- प्रत्येक तैनाती के बाद उत्पादन धुआं परीक्षण: /api/check, /api/explain,
  /api/followup।

## 7. सीमाएं और भविष्य का कार्य

- निष्कर्षण गुणवत्ता विवरण गुणवत्ता पर निर्भर करती है; प्रति-प्रश्न कम करता है
  लेकिन इसे समाप्त नहीं करता।
- वास्तविक-कॉन्फ़िग आयात बुनियादी है: MCP कॉन्फ़िगरेशन JSON क्लाइंट-साइड में
  सारांशित किया जाता है (सर्वर नाम, कमांड, URL)। अन्य निर्यात प्रारूप
  (सहायक सेटिंग्स, एजेंट फ्रेमवर्क कॉन्फ़िग) अभी पार्स नहीं होते।
- अभी कोई साझा करने योग्य निर्णय कार्ड / टीम दृश्य नहीं।
- ध्वनि इनपुट ब्राउज़र SpeechRecognition समर्थन पर निर्भर करता है।
- वर्तमान पांच से परे भाषाएं भविष्य का कार्य हैं।

## 8. हैकाथॉन रूब्रिक मानचित्रण (स्व-मूल्यांकन)

- **प्रभाव (30%)**: गैर-विशेषज्ञ एजेंट निर्माताओं की बढ़ती आबादी को
  लक्षित करता है; एजेंट को जोड़ने से पहले 30-सेकंड की जांच।
- **Meta टूलिंग (25%)**: निष्कर्षण, व्याख्या और वार्तालाप के लिए Meta Model API के माध्यम से
  Muse Spark पर निर्मित; डिज़ाइन ओपन-वेट
  पथ रखता है (परीक्षणों में निष्कर्षण/व्याख्या के लिए Muse Spark Open सत्यापित)।
- **तकनीकी गहराई (20%)**: मरम्मत सहित नियतात्मक इंजन + मान्य निष्कर्षण,
  निर्णय-बदलने वाला प्रति-प्रश्न तर्क, अनुवर्ती के लिए क्रिया प्रोटोकॉल।
- **डेमो (25%)**: 3-मिनट का चाप — Lethal ईमेल एजेंट → प्रति-प्रश्न → Risky + Low में
  विभाजन → ध्वनि + जापानी UI।
